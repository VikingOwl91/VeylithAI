## 8. Interpretation

| class | verdict |
|---|---|
| 1, valid clean replication with boundary exposure | **yes** |
| 2, valid clean replication without boundary exposure | no, exposure is present |
| 3, valid padded run with GPUVM fault | no |
| 4, invalid due to numerical or descriptor mismatch | no |
| 5, inconclusive | no |

Two independent clean runs, both with the protected operand read at the fault
geometry. The fault has appeared in three of three stock-geometry runs of this
configuration (PERF-5F A, PERF-5G A, PERF-5I).

What this supports: the product's storage boundary is associated with the fault
in this configuration, and the association reproduces.

What it does not establish:

1. Causality. Two clean runs with one intervention cannot separate the operand's
   boundary from the allocator layout change the intervention causes.
2. Kernel identity or the over-reading instruction, both unobserved.
3. That the remaining stock tail-4 read, the product gradient, is harmless. It
   was read at the same tail geometry and did not fault, which is evidence
   against "any tail-4 operand read faults", not evidence that it never faults.
4. Stability beyond these runs. Both clean runs share one harness, one driver,
   one device and one allocation pattern.

## 9. Confounders

1. Both clean runs use the same intervention, so their agreement is not
   independent of the mechanism's side effects on allocation layout.
2. Address reuse makes pointer matching unsafe alone; the analysis requires the
   byte count to match as well.
3. The post-loop recompute adds two forward and backward passes after
   `COMPLETED`; it cannot change the loop's outcome and is excluded by timestamp.
4. The product gradient stays unprotected in both runs, so a fault there would
   not have been prevented.

## 10. Recommended next bounded experiment

Swap the intervention rather than repeat it again: pad only the product's
gradient with the same `PaddedMul` mechanism applied to the elementwise outputs
that produce it, and leave the product stock. That covers the one remaining
stock tail-4 reader.

- A fault there would implicate the gradient consumer and lift the product
  hypothesis materially.
- A clean run there would leave the product as the only protected tail-4 operand
  in the campaign, which is the strongest available isolation without kernel
  identity.

If a third repetition of the current arm is preferred instead, it should be
justified as stability evidence, not as new discrimination.
