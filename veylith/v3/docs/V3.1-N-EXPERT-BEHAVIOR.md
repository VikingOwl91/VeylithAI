# v3.1-N expert behavior and routing profile

Status 2026-10-27. CPU-only, read-only profiling of the frozen v3.1-L
checkpoints on a bounded validation sample.

**Headline result.** The trained router is not uniform at the token level: it
routes punctuation, numeric, sentence-final and document-boundary tokens almost
deterministically to specific experts, while keeping global expert load
balanced. At step 500 the association between token form and expert choice
reaches 0.74 bits of Jensen-Shannon divergence for end-of-document tokens and
0.66 bits for numeric tokens in their strongest layers (0.67 and 0.58 on
average), far above every negative control. Position has no measurable effect.
Data-source conditioning is detectable but tiny (0.0014 to 0.0077 bits). The
router's assignment map is unrelated to initialization (12.4 percent agreement
versus 12.4 percent chance) but stable between updates 250 and 500 (82.1
percent top-expert agreement, mean total variation 0.078).

This is evidence for **routing specialization by token form**. It is not
evidence for functional expert specialization or for a predictive benefit;
those claims were not tested here.

## 3. Feature definitions

Derived from the actual SentencePiece pieces, not from words.

| feature | definition |
|---|---|
| `alpha` | piece core is alphabetic (word starts and continuations) |
| `numeric` | piece core is all digits |
| `punct_only` | piece core contains no alphanumeric character |
| `word_start` | piece begins with `▁` |
| `continuation` | alphabetic and not word-start |
| `capitalized` | piece contains an uppercase character |
| `sentence_end` | piece core contains `.`, `!` or `?` |
| `byte_fallback` | piece is a `<0x..>` byte-fallback token |
| `eos` | token id is the EOS id (document boundary) |
| `after_boundary` | window position 0, or previous token is EOS or PAD |
| `after_punct` | previous token is punctuation-only |
| `pos_early` | window position under 128 |
| `pos_mid` | window position 128 to 383 |
| `pos_late` | window position 384 or later |
| `freq_common` | token id in the top third of validation occurrence mass |
| `freq_rare` | token id in the bottom third of validation occurrence mass |

Token counts in the sample: alpha 104,915; word_start 72,849; continuation
35,569; numeric 2,247; punct_only 13,282; capitalized 14,970; sentence_end
4,228; byte_fallback 417; eos 109; after_boundary 349; after_punct 13,259;
freq_common 40,514; freq_rare 41,655; positions 30,480 to 61,440.

Exclusions and ambiguities:

- No non-special piece in this vocabulary mixes letters and digits, so the
  candidate `mixed_alnum` category is empty and was dropped. Byte-fallback
  pieces cover unusual characters.
- Categories overlap by design: `▁.` is punctuation, word-start and
  sentence-end. No exclusivity is assumed.
- BPE pieces are not words. `▁the` is a word start; `ing` is a continuation;
  `▁` alone is whitespace and occurs zero times in the sample.
- `sentence_end` is a surface test on `.`, `!`, `?`, not a parse.
- Positions are window positions inside a packed 512-token window, not
  document-relative positions.
- Frequencies come from the **validation split**, because no training-corpus
  token frequency table exists. This is a labelled proxy, not a training
  statistic.
- No POS tagger, parser or external linguistic resource was used.

## 4. Baseline verification

v3.1-M reported seven MoE layers, eight experts, top-2 routing, final
assignment entropy 0.999278 and shares 10.62 to 14.09 percent.

- Layers and experts: confirmed by the checkpoint configuration.
- The v3.1-M sample subset (first 40 sequences per source) reproduces its
  router confidence exactly: maximum absolute difference 1.4e-7 in normalized
  softmax entropy and 4.4e-8 in mean max probability at step 0; 1.9e-7 and
  1.0e-7 at step 500.
- The entropy and share figures differ from this report because of the metric,
  not a contradiction: v3.1-M computed entropy over **top-2 assignment
  counts** on the full validation split, while this analysis reports **top-1
  assignment** entropy on 240 sequences. Top-1 entropy at step 500 is 0.984 to
  0.996 and top-1 shares span 6.96 to 18.92 percent; counting both top-2
  choices mechanically compresses the marginal toward uniform. Both metrics
  agree that global load is balanced.
- v3.1-M's weak source conditioning, absent position effect and
  non-specialization finding are consistent with what follows, with the
  important addition of strong token-form routing.

No unexplained discrepancy was found.

## 5. Instrumentation equivalence

Router logits were captured with read-only forward hooks on each MoE gate. The
instrumented forward pass reproduces the ordinary pass exactly:

- maximum absolute difference in final logits: **0.0** (stated tolerance 1e-5);
- probe top-1 equals the forward pass's returned router indices for all seven

All thirteen token-form features are beyond the null in all seven layers at
q = 0.0037, the smallest adjusted value in this family (the raw permutation
floor with 300 permutations is 0.0033; Benjamini-Hochberg raises it slightly
because the family also contains larger p-values for position features). No
position feature is significant after correction. Stratifying by source or by position
bucket leaves the token-form effects essentially unchanged, so they are not
domain or position artifacts.

The EOS interval is degenerate (0.740 to 0.740) because every one of the 109
EOS tokens takes the same expert in the resampled data as well; the
permutation null (95th percentile 0.0233) is the meaningful comparison for that
feature.

### Conditional distributions

The router's conditional behavior is much sharper than the global balance
suggests. Top-1 shares by feature at step 500, layers 1 to 7 (expert index and
share of that feature's tokens):

| feature | L1 | L2 | L3 | L4 | L5 | L6 | L7 |
|---|---|---|---|---|---|---|---|
| eos | E3 100% | E2 100% | E1 100% | E5 100% | E6 100% | E4 78% | E0 94% |
| numeric | E3 48%, E6 43% | E1 94% | E6 95% | E4 80% | E7 91% | E4 98% | E0 82% |
| sentence_end | E3 99% | E2 84% | E1 83% | E7 70% | E7 39%, E3 34% | E4 54% | E0 63% |
| punct_only | E3 55%, E2 37% | E2 47% | E1 49% | E7 44% | E1 29% | E4 43%, E5 36% | E0 34% |
| capitalized | E3 48% | E1 33% | E1 30% | E5 47% | E6 47% | E2 39% | E6 36% |

For comparison, layer 1 global shares at step 500 are 13.8, 12.4, 16.9, 15.3,
15.0, 9.6, 10.1 and 7.0 percent. Expert 3 receives every EOS token, 48 percent
of numerics, 55 percent of punctuation and 48 percent of capitalized tokens,
yet still only 16.9 percent of all tokens, because those classes are a small
share of the stream. This is how strong conditional routing coexists with
balanced global utilization.

## 8. Significance versus practical importance

At step 0, 77 of 112 tests pass the "beyond null" rule, but the median feature
JS is 0.0012 bits and the significant effects are tiny (position buckets 0.0001
to 0.016, sentence-end 0.003 to 0.012, punctuation 0.001 to 0.005,
after-boundary 0.012 to 0.032). The 95th null percentile is about 0.0003, so
even a 0.01-bit effect is "significant". This is the clearest example in the
experiment of statistical significance without practical importance: the
random router responds weakly to hidden-state differences by position and token
class, and a tight null makes that detectable.

At step 500 the situation reverses: median JS 0.081 bits, with token-form
effects from 0.0075 to 0.74 bits. These are both significant and large.

Rare categories need care. At step 0, EOS (n=109) has JS up to 0.09 and
byte-fallback (n=417) up to 0.075, yet neither survives correction (q 0.45 and
0.80), because their null distributions are wide. Conversely their step-500
effects are decisive and their CIs exclude zero.

## 9. Negative controls

| control | median JS | interpretation |
|---|---:|---|
| within-sequence expert permutation (primary null) | 0.000115 | preserves per-sequence expert mix |
| within-sequence feature-label permutation | 0.000112 | agrees with the primary null to 3e-6, as expected |
| global frequency-matched expert shuffle | 0.00596 | destroys sequence structure, inflates noise; per-feature medians 0.0057 to 0.0166 |
| position-only features, observed | 0.00003 to 0.00024 | indistinguishable from noise after correction |
| source labels, observed at 500 | 0.0014 to 0.0039 | significant but 0.2 to 1.1 percent of ceiling |

The primary null is the appropriate one: it keeps each sequence's expert
multiset fixed and asks whether the feature carries information beyond that.
The global shuffle is reported as a contrasting, weaker control, not as the
primary test.

## 10. Step 0 versus step 500

**The assignment map is reorganized, not refined.** For the same 122,640
tokens, top-1 agreement between step 0 and step 500 is 0.120 to 0.128 per
layer, against chance agreement of 0.120 to 0.128 computed from the two
marginals. Expert index correspondence is nevertheless real: the cosine
between expert weight vectors at the two checkpoints is 0.956 to 0.970 on the
diagonal, at most 0.0023 off-diagonal, and the diagonal is the argmax in every
layer. The experts kept their lineage; their routing choices did not.

**Preferences emerged and then stabilized.** Median feature JS and the number
of beyond-null tests:

| step | median JS | beyond-null tests | JS profile correlation with step 500 |
|---:|---:|---:|---:|
| 0 | 0.00118 | 77 | 0.46 |
| 100 | 0.06633 | 112 | 0.83 |
| 250 | 0.08095 | 107 | 0.99 |
| 500 | 0.08116 | 105 | 1.00 |

Mean absolute JS change is 0.121 from 0 to 100, 0.068 from 100 to 250 and
0.018 from 250 to 500. The association profile is essentially fixed after
update 250.

**Expert identity is stable between 250 and 500.** Across the 112
feature-layer cells, the top expert is the same at both checkpoints in 82.1
percent of cells, and the mean total-variation distance between conditional
distributions is 0.078. Against step 0 the same numbers are 8.9 percent and
0.421. Concrete examples: numeric at layer 1 stays on expert 3 (79.9 to 47.5
percent, the largest drift), punctuation at layer 4 stays on expert 7 (39.8 to
43.8 percent), EOS keeps its single expert in layers 1 to 5.

This supports "stable, learned routing preferences" for the measured window.
It does not prove stability across seeds, datasets or longer training.

## 11. The six claims

| claim | status |
|---|---|
| 1. Balanced expert utilization | **measured, yes**: top-1 entropy 0.984 to 0.996, global shares 7.0 to 18.9 percent per layer |
| 2. Confident per-token routing | **measured, yes**: softmax entropy 0.62 to 0.87, max probability 0.35 to 0.58 |
| 3. Routing correlates with token features | **measured, yes and strong** for token form (0.0075 to 0.74 bits); weak for source (0.0014 to 0.0039); absent for position |
| 4. Stable, learned preferences | **measured, yes within the window**: near-null at init, present by update 100, 82 percent top-expert agreement and 0.078 total variation between 250 and 500 |
| 5. Functional expert specialization | **not established**: expert outputs were more similar at step 500 than at init in v3.1-M, and this experiment did not test expert function |
| 6. Predictive benefit | **not established**: no routing ablation was run |

The distinction matters: a strong token-type partition in routing is not the
same as experts that compute different things, and neither is the same as a
measurable loss benefit.

## 12. Limitations and uncertainties

- One training run, one seed, one deterministic sample of 240 sequences from
  the first ten batches per source. Sequences are contiguous document pools, so
  document-level clustering remains; the sequence bootstrap accounts for
  within-sequence correlation but not for shared documents across sequences.
- Associations use top-1 assignment only. The routing rule is top-2 with
  weights; the second expert and the weight magnitude were not modeled.
- Features are surface-level. No syntax, semantics or word identity beyond
  frequency tertiles. A lexical probe was not run.
- EOS has 109 tokens and byte-fallback 417; their estimates are less stable,
  and the EOS bootstrap interval is degenerate.
- Frequencies are validation-derived, not training-corpus frequencies.
- Expert IDs are arbitrary; correspondence is inferred from weight cosine, not
  from an external label.
- The v3.1-M comparison uses a different assignment metric (top-2 counts,
  full validation) and is not numerically interchangeable with this report.
- The 20-minute analysis budget and the 10-minute inference cap were respected
  for the artifact pipeline (496 s of inference, 598 s total). Development
  passes, including one superseded conditional run and smoke tests, brought
  cumulative inference to about 700 s.
- No statistical claim here survives an adversarial relabeling of experts, but
  none needs to: the analysis is invariant to expert index permutation.

## 13. Recommendation for v3.1-O

**Primary: an inference-time routing ablation.** On a bounded validation
sample, override the router for one token class at a time (for example force
numeric or EOS tokens to a uniform distribution over experts, or to a
different expert) and measure the change in cross-entropy by token class,
using the same frozen checkpoint. This directly tests claim 6, costs CPU time
only, changes no weights and needs no architecture change. It answers whether
the learned class routing actually helps prediction or is an epiphenomenon of
the auxiliary loss.

Secondary options, in order:

2. **Expert-contribution ablation**: zero or scale one expert's contribution
   per layer and measure CE by token class. This tests claim 5 (functional
   specialization) and complements the v3.1-M output-similarity result.
3. **Continue Dense-Combined training** to see whether functional divergence
   follows routing specialization. This needs a new GPU authorization and a
   budget; the routing preferences are already stable by update 250, so the
   open question is expert function, not router structure.

All three keep Architecture A unchanged. Option 1 is the cheapest and most
informative next step, and it is the only one that can be done without new
training.
