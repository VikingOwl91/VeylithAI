# v3.1-A GPU smoke plan (proposal only, not approved)

Status 2026-10-27. This is a plan for the next, separately approved phase.
No GPU run is authorized by this document.

## Goal

Prove that architecture A trains on the RX 9070 XT (16 GB, ROCm 7.2, bf16)
without faults, with a measured memory/step budget, before any real
pretraining run.

## Risks and gates

| risk | gate |
|---|---|
| sparse MoE ROCm fault (v2 E16/K4 history) | run a bounded sparse smoke; on fault stop, do not retry, switch to dense-combined only with explicit approval |
| SDPA mask/backend incompatibility | CPU parity test passed; on GPU compare a short manual vs SDPA step, fail explicitly if unsupported |
| VRAM overrun | start microbatch 1, seq 512; measure allocated/reserved; increase only while below 14 GB |
| step time too high | measure 20 steps after 5 warmup; compare with the analytical 4 GB / 0.5 h estimate |
| hang/OOM/NaN | stop immediately, save logs/artifacts, no automatic restart |
| optimizer/resume mismatch | run a 4-step stop/resume on GPU before the longer smoke |

## Test matrix

1. Model A, bf16, SDPA, sparse, microbatch 1, seq 512, 10 steps: forward,
   backward, optimizer step; check finite loss/grads, router entropy, VRAM.
2. If green: microbatch 2/4/8, 5 steps each, record peak allocated/reserved.
3. Attention: manual vs SDPA on the same batch, forward/grad tolerance.
4. Dense-combined fallback: microbatch 1, 5 steps, record compute/memory.
5. Resume: stop at 4, resume, compare loss/weights within backend tolerance.
6. Total duration cap: 30 minutes of GPU time, no dataset generation.

## Stop conditions

Any fault, OOM, NaN/Inf, hang over 120 s per step, or a router collapse
(entropy < 0.2 or unused experts > 0) stops the smoke. Save the log and the
last state, report, and wait for instructions. No retry loop, no alternative
GPU configuration without approval.

## Measurements to record

- exact command, torch/ROCm versions, allocator env;
- step time, tokens/s, peak allocated/reserved VRAM, per-phase profile;
- loss curve, grad norm, router entropy/share, tokens seen;
- checkpoint/resume equality within tolerance;
- any fault signature with full log.

## After the smoke

Only then define the real training run (data budget, steps, LR, stop rule)
and request a separate GPU approval. The 95.95M-token corpus is ~1 token per
parameter; a 500M-1B-token corpus is the recommended next data step.
