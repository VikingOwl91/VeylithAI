# v3.1-J isolated Sparse-MoE fault reproduction

Status 2026-10-27. One bounded GPU reproducer execution in
`~/veylith-v31-isolated`. No training, no optimizer updates on a Veylith
model, no checkpoint writes, no retry and no fallback.

## Answer

**Yes. The historical BF16 Sparse-MoE GPU memory access fault reproduces with
the isolated PyTorch 2.14.1+rocm7.2 wheel on the same RX 9070 XT.**

Classification: **A. Reproduced fault.** Python and ROCm user-space isolation
alone did not eliminate the historical issue.

## Comparability limitations

- The managed Python 3.14.8 build differs from the historical system Python
  build, although the language version is the same.
- The isolated wheel bundles ROCm 7.2 user-space; the historical system build
  used `/opt/rocm` 7.2.4. Both report HIP 7.2.53211 and torch 2.14.1.
- One isolated execution was authorized. The historical result is 4/4 faults;
  the isolated result is 1/1 fault. This is a reproduction, not a new rate
  estimate.
- The exact faulting iteration, peak GPU memory and dying-process library map
  are not available after the abort.
- GPU compute responsiveness after the fault was not tested; only read-only
  management queries were run.
