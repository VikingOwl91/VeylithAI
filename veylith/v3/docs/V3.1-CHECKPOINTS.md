# v3.1-A checkpoints and resume

Status 2026-10-27. CPU-validated; bounded GPU runs use the same format.

## Two files

| file | contents | use |
|---|---|---|
| state (`ckpt_state_step{step}.pt`) | model, optimizer, schedule, step, tokens, loader epoch/batch, best metric/step/tokens/weights, RNG, config, data hash, fingerprint, versions | resume |
| artifact (`ckpt_best.pt`) | best weights, model/train config, tokenizer, data hash, selection record, metrics, best-step token count, versions | inference/evaluation |

Writes are atomic: temp file, fsync, `os.replace`, directory fsync. A crash
cannot leave a truncated file. A run writes the state at `save_steps` and at
the stop step; the artifact only when a full run completes. Use a
step-suffixed state path for any run with multiple milestones; a fixed path
overwrites earlier states (the v3.1-D pilot did this at step 50).
`checkpoints.jsonl` records each write's step, token count, bytes, free disk,
and sha256.

## Resume

- Fingerprint = model config + data manifest sha256 + device, precision,
  microbatch, accumulation, sequence, LR schedule, optimizer, clipping, seed,
  deterministic mode, selection metric.
- Excluded from the fingerprint: `max_steps` (extending a run is allowed),
  `stop_after`, evaluation/save intervals, paths, log intervals.
- Resume restores model, optimizer (tensors moved to the device), schedule,
  RNG (python/numpy/torch/cuda), step, token counter, loader position,
  best state and the token count of the best step. The loader resumes at
  `(epoch, batch)` deterministically. The first resumed update records a
  `resume_trace` (loader position, first batch indices, order digest) in the
  curve.
- A changed model, data manifest or optimizer setting raises a clear
  fingerprint error. A changed `max_steps` is allowed.
- No MTP fields exist in v3.1-A states or artifacts; adding MTP later needs a
  new optional field, not a silent format change.

## Selection

Validation only, metric `macro_main_ce` by default (equal source weight;
`token_main_ce` is available). The best weights and validation metrics are
stored in the state and copied into the artifact. Test metrics are never a
selection signal. The artifact records `selection.step`, metric and value,
and `tokens_seen` for that best step (not the final token count).

## Evidence

`test_resume_matches_uninterrupted_run`: 4 steps, stop at 2, resume, compare
the final model tensors and token counter with the uninterrupted run.
`test_resume_rejects_a_changed_fingerprint`: a wrong fingerprint is rejected.
CPU reference uses dropout 0 for exact comparison; a GPU run is deterministic
only to the extent the backend ops allow.
