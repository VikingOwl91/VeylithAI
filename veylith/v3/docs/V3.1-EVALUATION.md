# v3.1-A evaluation protocol

Status 2026-10-26. Protocol only; no run exists.

## 1. Data and splits

| split | tokens | documents | use |
|---|---:|---:|---|
| train | 95,951,233 | 87,063 | single-pass training only |
| validation | 2,122,377 | 1,874 | checkpoint selection, early stopping, ablation decisions |
| test | 2,094,292 | 1,847 | final report only, untouched during development |

The split is document-hash based across FineWeb-Edu, Wikipedia and
Cosmopedia v2 (2 % each). The test split must not be read for selection,
hyperparameters or tokenizer decisions.

## 2. Per-source metrics

For each source and overall:

| metric | definition |
|---|---|
| main CE | next-token cross-entropy on the held-out tokens, no MTP, no aux |
| perplexity | exp(main CE) |
| bits/char | total nats over evaluated targets divided by the exact character span (prefix decodes) |
| token count | tokens per source and split |
| loss share | weighted contribution of each source to the overall CE |

Report both a **token-weighted overall CE** (dominated by FineWeb, 63 %) and
a **macro average over sources** (each source equal). Never report only the
pooled number.

## 3. Train/validation divergence

- Hold out fixed train sections, stratified by source (for example 1M
  characters per source), and measure train main CE on them.
- Report val minus train in nats/token and bits/char.
- The v2 experience: a growing gap after the early minimum is the signal to
  stop, not a reason to keep training.
- Selection metric: macro validation main CE (equal source weight) for the
  multi-source model; also record the token-weighted value. Do not select on
  the test split.

## 4. Router and MoE health

Per MoE layer, on held-out text:

- normalized entropy of the mean router distribution;
- min/max expert share and unused experts;
- routed fraction per expert (assignment share);
- aux loss value;
- optional: per-source router distribution to detect source-specific
  collapse.

A healthy router uses all 8 experts with no near-zero share. A collapsed or
single-source-dominated router is a failure, not a quality result.

## 5. Baselines

Same tokenizer, data, splits and evaluation:

1. **v2 MoE 25.6M** with the 8192 vocabulary (29.28M total; 13.57M active
   under the audit convention) as the historical reference.
2. **Smaller MoE 17.3M** (8.43M active at 8192) from the earlier design note.
3. **Dense 6x256 8.32M** (all active) as a compute-matched dense baseline.
4. Candidate A primary; C fallback; B/D only as ablations.

The baselines are comparison points, not claims of superiority. No raw token
loss comparison across tokenizers; use bits/char on the same text.

## 6. Throughput, memory and reproducibility

For each GPU run (later, with separate approval):

- step time, tokens/s, peak allocated/reserved VRAM, phase profile;
- microbatch and gradient accumulation, effective batch 64;
- seed, config hash, tokenizer hash, data manifest digest;
- checkpoint step and selection record, optimizer/RNG state, resume check;
- exact command and environment (torch/ROCm, allocator env).

The CPU reference tests for the architecture are
`veylith/v3/tests/test_architecture.py`: counts, forward shapes, causal mask,
router selection, finite outputs, tiny backward, memory/compute estimates.

## 7. Contamination and data risks

- Cosmopedia v2 was generated from FineWeb seeds; near-duplicate dedup removes
  near-identical text, not semantic overlap. A FineWeb-seeded synthetic
  passage can resemble its seed; per-source metrics and a manual spot check
  are required.
- Wikipedia and FineWeb can cover the same facts; exact/near dedup found 0
  cross-source duplicates in this sample, which is not proof of no semantic
  overlap.
- Synthetic text can be stale or hallucinated; evaluate Cosmopedia separately.
- Python-Edu is missing; results cannot be attributed to code data.
- Do not use Shakespeare-only evaluation as a primary measure.

## 8. MTP ablation protocol (later)

Only after the baseline exists: same data, seed, steps and schedule; w=0.0
baseline against w=0.2 and w=0.5 (shared head, t+2). Compare main CE and
bits/char per source, MTP CE, train/val gap, router health, generation and
compute overhead. A benefit counts only if the main objective improves on the
frozen test split without a routing/calibration regression.

## 9. Gates before the first training run

1. Architecture tests green (this task).
2. Training implementation with checkpoint/resume and no MTP metadata.
3. Bounded GPU sparse-fault smoke test; dense-combined fallback documented.
4. A short CPU/gpu smoke run with loss decreasing and router health.
5. Explicit GPU approval and a fixed command.
6. Test split never touched before the final evaluation.
