# v3.1-A GPU compatibility smoke results (2026-10-27)

Authorized bounded smoke on the AMD Radeon RX 9070 XT. No pretraining, no
dataset downloads, no checkpoint writes, no dense-combined fallback. All run
artifacts live outside Git at
`~/veylith-v31-gpu-smoke-20261027/`; only the small summary JSON is
committed.

| item | value |

| Kernel | 7.2.11-zen1-1.1-zen |
| Mesa | 26.2.5-arch1.1.1 |

The system ROCm PyTorch was used through the isolated venv. No system
package, driver or kernel change was made.

## 2. Attempts

1. First launch was started with `HIP_VISIBLE_DEVICES=""` (a leftover from the
   CPU guard). The GPU was hidden; the harness stopped at preflight before any
   GPU work. Corrected visibility and re-ran.
2. Second launch: baseline and SDPA passed; the sparse MoE hit
   `index_add_(): self (BFloat16) and source (Float) must have the same scalar
   type`. This is a bf16 dtype bug in the reference MoE, not a GPU fault. The
   expert contribution is now cast to the output dtype in both sparse and
   dense paths; a CPU bf16 regression test was added.
3. Final run: baseline, SDPA, sparse MoE and full Architecture A all passed.
   Total measured smoke time 8.3 s, well under the 30-minute budget.

## 6. Full Architecture A

BF16 autocast, fp32 master weights, SDPA, sparse top-2, context 512,
synthetic token IDs, 5 steps per microbatch, gradient clipping, no
checkpoints. The first step includes optimizer-state allocation and kernel
warmup; the median is over 5 steps.

|---:|---:|---:|---:|---:|---:|---:|---|
| 1 | 0.103 s | 4,966 | 2.14 GB | 2.56 GB | 9.1455 | 9.62 | 0.50-0.93 |
| 2 | 0.106 s | 9,669 | 2.16 GB | 2.67 GB | 9.1225 | 8.50 | 0.61-0.94 |

No NaN/Inf, no OOM, no fault, no step above 120 s. The router entropy at

microbatch 8 is 0.87-0.97. No severe collapse was observed, but the short
random batch is not a router-quality measurement.

## 7. Faults and GPU state

- No GPU fault, no reset, no HIP error, no OOM, no NaN/Inf.
- After the run: no KFD PIDs, VRAM back to 1.69 GB baseline.
- The only stop was the bf16 dtype error in attempt 2, fixed before the final
  run; it was not a GPU fault.

## 8. Comparison with analytical estimates

- Analytical MB8 memory: 4.04 GB total including 1.9 GB reserved context and
  12 % margin. Measured tensor peaks: 3.40 GB allocated, 3.58 GB reserved.
  The analytical budget is conservative and the card has ample headroom.
- Analytical wall clock for 95.95M tokens: about 0.49 h. Measured MB8
  throughput is 27,345 tokens/s, so 95.95M tokens would take about 0.97 h
  (3,509 s), roughly 2x the analytical estimate. The estimate was optimistic
  for this kernel/stack.
- Sparse execution worked at A width; dense-combined was not run and is not
  authorized.

## 9. Recommendation

1. The stack is compatible with Architecture A for a bounded run: SDPA with
   causal/SWA bool masks, sparse top-2 MoE, bf16 autocast, MB8 at 3.4-3.6 GB
   and about 0.15 s/step on random tokens.
2. Do not start pretraining yet. A longer bounded GPU validation (for example
   100-500 steps on real shards) should check loss behavior, router health
   and fault stability before a full run.
3. Keep the 30-minute/no-retry discipline for that validation.
4. If a fault appears later, stop and report; dense-combined remains a
   separate decision, not an automatic fallback.
5. The analytical 2x wall-clock gap should be treated as the planning number
   (about 1 h for one 95.95M-token pass at MB8), not the 0.49 h lower bound.

## 10. Reproduction

```bash
~/veylith-v31-gpu-env/bin/python veylith/v3/gpu_smoke.py \
    --out ~/veylith-v31-gpu-smoke-20261027/run3
```

The four phases are baseline, SDPA, MoE and full A. The harness enforces a
30-minute budget and a 120 s per-step alarm, stops on the first error and
never retries. The committed summary is
`veylith/v3/docs/gpu-smoke-2026-10-27-summary.json`; logs stay outside Git.
