# v3.1-A training infrastructure

Status 2026-10-27. CPU-only reference trainer. No GPU run, no full 0.1B CPU
training, no model quality claim. Architecture A is defined in
`V3.1-ARCHITECTURE.md`. MTP is absent.

## 1. Scope

`veylith/v3/training/` implements the next-token training loop, evaluation,
checkpointing/resume and the CPU validation harness. It does **not** download
data, touch ROCm/drivers, or run the 0.1B model on CPU: a guard refuses any
CPU run above 5M parameters.

## 2. Loop

- Next-token cross-entropy with padding mask; optional Switch-style router aux
  (`model.moe_aux_weight`, default 0.01); no MTP term or metric.
- AdamW with configurable betas/eps/weight decay; 2D weights decay, 1D norms
  do not. The optimizer groups are derived from the model.
- Linear warmup + cosine to `min_lr_ratio`; step-based, no external scheduler.
- Microbatch (`batch_size`) times gradient accumulation (`grad_accum`) equals
  the effective batch. The default 8 x 8 = 64 at sequence 512.
- Loss for an accumulation window:
  `sum_i(ce_sum_i + w * aux_i * valid_i) / sum_i(valid_i)`.
  This gives the token-weighted main CE and the token-weighted aux mean.
- Gradient clipping after the accumulation, configurable (`0` disables).
- Deterministic seeds (`python`, `numpy`, `torch`), single CPU thread and
  `torch.use_deterministic_algorithms(True)` for the CPU reference.
- Precision: fp32 (CPU reference); bf16 is accepted only on CUDA
  (`torch.autocast`). CPU bf16 is rejected.
- Structured JSONL metrics: step, lr, tokens, train main/aux/loss, grad norm,
  elapsed time, validation per source, router stats and train/val gap.

**Aux and accumulation:** the aux is a product of two per-microbatch means.
Its accumulation is therefore not exactly equal to one large batch. The main
CE is exact; the difference is documented and tested separately (the
equivalence test runs with aux weight 0). This is a property of the Switch
loss, not of the optimizer.

## 3. Attention and MoE paths

- `attention_impl="manual"` (reference) or `"sdpa"` (same bool causal/SWA mask,
  GQA via repeated KV heads). SDPA failures raise explicitly; no silent
  semantics change.
- `moe_impl="sparse"` (top-k experts only) or `"dense"` (all experts with the
  same routing weights). The router, aux and weights are identical; only the
  compute path differs.
- CPU tests compare forward outputs and gradients: attention manual vs SDPA,
  MoE sparse vs dense (tolerances 1e-5 forward, 1e-4 gradients).

## 3.1 Router-aux audit (2026-10-27)

Per MoE layer:

`aux_layer = E * sum_e (assignment_fraction_e * mean_router_prob_e)`.

For balanced routing both distributions are uniform and the per-layer value
is 1.0. The model returns the **sum over the 7 MoE layers**, so a balanced
model reports 7.0. The GPU smoke's 7.44-9.62 is therefore 1.06-1.37 per
layer, not a normalization bug. The 0.01 coefficient applies to the sum
(0.01 per layer); at main CE 9.1 the contribution is about 0.07 nats
(under 1 %). The first real run logged 1.067 (step 10) to 1.003 (step 100)
per layer.

The aux gradient reaches the router; gradient accumulation weights it by
token count, so it is the token-weighted mean. Diagnostics added:
`aux_loss_per_layer` in model metrics, `train_aux_per_layer` and
`train_aux_weighted` in the curve. A CPU test proves the uniform-router
baseline (1.0 per layer, sum = number of MoE layers). The objective is
unchanged.

## 4. Evaluation

`evaluate(model, cfg, split, max_batches=...)` uses the frozen token shards,
source-pure packing (no sequence mixes sources), and reports per source:
main CE, bits/char, tokens, chars, aux; plus token-weighted overall CE, macro
overall CE and router entropy/share. Validation is for selection; test is
final. The trainer only evaluates validation (selection) and a bounded train
sample (gap). Bits/char uses proportional character shares per document; the
final test report can use the exact P1-2 prefix-decode protocol.

## 5. CPU smoke tests

`veylith/v3/tests/test_training.py`: attention/MoE path parity (forward and
gradients), gradient accumulation equivalence (main CE), tiny loss decrease,
checkpoint resume vs uninterrupted, evaluation metrics, artifact selection,
incompatible resume, CPU guard. `test_architecture.py` covers counts and
forward/mask/router behavior. No full-size forward/backward.

## 6. Usage (GPU is not approved)

```bash
python3 veylith/v3/train_v31.py --data-root ~/veylith-v3-data/multi-100m-20261026 \
    --out-dir ~/veylith-v3-runs/v31-a --model A --device cpu --max-steps 4
# -> refuses: a 98M model is not trained on CPU in this phase
```

The CPU smoke tests call `training.train.train()` with a tiny model and a
tiny synthetic corpus. The future GPU command uses `--device cuda`, `--precision
bf16`, `--attention sdpa`, `--moe sparse` (or dense fallback) and the same
config fields.

## 7. Open risks

- Sparse MoE on ROCm is unresolved; dense-combined is the fallback.
- The CPU reference uses manual attention; SDPA on GPU must be parity-checked.
- The aux/accumulation caveat above.
- No full-size CPU forward/backward; VRAM numbers remain analytical.
- No GPU run is approved.
