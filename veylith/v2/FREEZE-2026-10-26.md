# veylith v2 research freeze (2026-10-26)

This document closes veylith v2 as a reproducible research baseline. It is
the reference for every later comparison. Anything not recorded here is not
part of the frozen state.

Tag: `v2-research-freeze-2026-10-26`. The tag points at the commit that adds
this document. v2 files are not modified after that tag; v3 development
happens on `v3/data-pipeline`.

Evidence labels, as in the earlier reports: measured here, stored in a
checkpoint, reconstructed from code and arguments, reported by an earlier
log, or not determinable.

| field | value |
|---|---|
| layers | 6, pre-norm residual |
| width | 256, 8 query heads, 2 KV heads (GQA) |
| context | block 256 |
| attention | RoPE, sliding window 128, full attention every 4th layer |

| MLP | SwiGLU, ratio 8/3; layer 0 dense, layers 1..5 MoE |

## 4. Training protocol (P1-3, the frozen v2 run)

- one GPU run, 5000 steps, batch 64, block 256, BPE 1000, seed 1337
- lr 3e-4, warmup 100, cosine to 10 %, dropout 0.1, bf16 autocast
- dense-combined MoE path, no sparse configuration
- evaluation every 250 steps on fixed sections, main-CE selection only
- `PYTORCH_HIP_ALLOC_CONF=roundup_power2_divisions:4` set before the process
- 81,920,000 training tokens, 166.2 passes over 492,841 BPE tokens
- best checkpoint at step 500, last trained step 4999
- exact command and log: `veylith/evaluation/P1-3-REPORT.md`

Historical v2 run (before P1-3): 3000 steps, same batch/block/lr, composite
selection, artifact records `args.max_iters=3000` and `val_loss=6.0358`,
but no step, metrics or selection record (legacy format). The selected step
500 is documented in commit `347aa70`, not in the artifact.

## 5. Evaluation protocol (P1-2, frozen)

- six fixed validation sections, 512 characters, 128-character gap, starting
  at character 1,008,119 (after both tokenizers' validation splits)
- 3067 evaluated characters, 1377 BPE tokens, identical text for v1 and v2
- main next-token cross-entropy only, no MTP and no aux term
- bits/char = nats over evaluated targets / exact character span of those
  targets (prefix decodes), not a corpus-average conversion
- no comparison of raw token losses across tokenizers
- checkpoint selection uses a separate fixed set: six sections from
  1,050,000 (see `evaluation/selection-sections.json`), never the test
  sections; selection metric is main CE

## 6. Results

Frozen comparison on the six test sections:

| model | main CE | perplexity | bits/char |
|---|---:|---:|---:|
| v1-char | 1.3262 | 3.77 | 1.9133 |
| v1-BPE | 2.9671 | 19.44 | 1.9219 |
| v1-BPE 5000it | 3.7158 | 41.09 | 2.4069 |
| v2-BPE shipped (composite selection) | 3.1800 | 24.05 | 2.0598 |
| v2-BPE P1-3 (step 500, main-CE selection) | 3.1581 | 23.53 | 2.0456 |
| v2-P1-1 diagnostic (120 steps) | 4.6701 | 106.71 | 3.0250 |

Paired over the six sections:

| comparison | nats/token | 95 % CI | bits/char | 95 % CI |
|---|---:|---|---:|---|
| shipped v2 - v1-BPE | +0.2127 +/- 0.0381 | +0.1147..+0.3107 | +0.1378 +/- 0.0254 | +0.0726..+0.2031 |
| P1-3 v2 - shipped v2 | -0.0237 +/- 0.0264 | -0.0915..+0.0441 | -0.0142 +/- 0.0167 | -0.0571..+0.0288 |
| P1-3 v2 - v1-BPE | +0.1890 +/- 0.0336 | +0.1028..+0.2753 | +0.1237 +/- 0.0227 | +0.0652..+0.1821 |

The P1-3 improvement over the shipped checkpoint is inside one standard
error. The deficit to v1-BPE remains 5.6 standard errors. The frozen
conclusion is: v2 does not reach v1 on this corpus at this budget, and the
small P1-3 gain is not attributable to the changed selection criterion
(both criteria select step 500 in that run).

## 7. P1-3 run: early overfitting

Selection CE on the fixed selection sections:

| step | 0 | 250 | 500 | 750 | 1000 | 2500 | 4999 |
|---|---:|---:|---:|---:|---:|---:|---:|
| val main CE | 6.9695 | 3.6153 | **3.2779** | 3.4722 | 3.8224 | 4.6625 | 4.7500 |
| train main CE | 6.9569 | 3.4389 | 2.6599 | 1.9333 | 1.3487 | 0.5849 | 0.5878 |

The validation minimum is at step 500; afterwards the model memorizes the
training split. The composite also bottoms at step 500 (5.7912), so the
selection change did not pick a different step. Fixed-section gap at the
selected checkpoint: train 2.6604, val 3.1581, gap +0.4977 (shipped v2:
+0.4248; v1-BPE: +0.4707). The new model fits train better and generalizes
slightly better; the gap grew because the train side fell more.

## 8. Router and MTP

Router on the test sections (P1-3 checkpoint): all 8 experts used in all 5
MoE layers, normalised entropy 0.776..0.833, shares 8.1..16.5 %, no unused
expert, no collapse. Shipped v2: 0.763..0.841, 9.2..16.6 %. Selection
depends on the text section; the frozen reports record the per-section
deviation and TV distance.

MTP at the selected checkpoint: 43.2 % of the composite value, 55.9 % main,
0.92 % aux. Gradient cosine between main and MTP +0.220 (shipped v2:
+0.240). MTP is aligned with the main objective but consumes a large share
of the value and gradient; removing it is an experiment for v3, not a
change to the frozen baseline.

## 9. Reproducibility, limitations, GPU status

Reproducibility evidence:

- 89 CPU tests green at the freeze commit; no test initializes a GPU.
- Two independent CPU evaluation runs produced byte-identical payloads
  (`p1-3-results.json` and a second run), including router and generation.
- The real P1-3 training state passes `load_train_state` with the run's
  exact arguments (config fingerprint and section hash match).
- The artifact weights are bit-identical to the state's `best_model`, so
  the artifact is the step-500 selection.
- GPU training determinism is not claimed; the run was executed once.

Known limitations:

- one run, one seed, no seed variance
- six 512-character sections per evaluation and selection; small samples
- the shipped v2 checkpoint has no stored step or metrics; its selection
  step is documentation only
- no patience-based early stopping; the main-CE selection keeps the early
  minimum but the run still spent 4500 steps past it
- the corpus is Tiny Shakespeare, 0.44M training tokens; the result says
  nothing about larger corpora
- v1's selected step is not determinable

ROCm/GPU status (frozen): system torch 2.14.1 with ROCm 7.2.53211. The
sparse-MoE path is not adopted. The deterministic reproducer faults on
2.14.1 and on nightlies through 20261001; a 16-expert top-4 configuration
still aborted on 2.16.0.dev20261006, so the fault is not fixed in general.
`PYTORCH_HIP_ALLOC_CONF=roundup_power2_divisions:4` is a workaround
candidate, not a fix. The dense-combined path completed the 5000-step
P1-3 run with the variable set. No ROCm, PyTorch, kernel or driver change
is part of this freeze. Full evidence: `veylith/debug/README.md`,
`phase4-scaling.md` and the E16/K4 archive (not submitted upstream).

## 11. Frozen interfaces

- Artifact format: `format: 2`, `kind: model`, fields `model`, `config`,
  `tokenizer`, `val_loss`, `metrics`, `selection {metric, value, step}`,
  `evaluation`, `step`, `args`.
- Resume state: `format: 2`, `kind: train_state`, plus optimizer, RNG and
  `best_step`; resume refuses a changed config, evaluation mode, metric or
  selection-section hash.
- Evaluation constants: six sections at 1,008,119, width 512, gap 128,
  main CE only.
- Selection constants: six sections at 1,050,000, main CE, best step.
- v3 must not reuse the P1-2 test sections for training or selection.

## 12. What v3 inherits

- the v2 architecture as the reference model, unchanged for the first v3
  data-only iteration
- the bits/char protocol, so new tokenizers remain comparable
- the rule that data preparation is CPU-only and separate from GPU training
- the lesson that 25.6M parameters on 0.44M tokens overfit after 500 steps;
  v3 changes the data first, not the architecture
